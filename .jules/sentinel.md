## 2024-05-24 - [Fix weak PRNG vulnerability in client device ID generation]
**Vulnerability:** Weak PRNG (`Math.random()`) was being used in `src/util/subscription.js` to generate a `device_id` string, which is then bound directly to the subscription JWT during verification. `Math.random()` generates cryptographically insecure, predictable output.
**Learning:** `device_id` values bind the access token (ECDSA-signed JWT) securely to a specific device payload, preventing token replay attacks or sharing. Because this token binding is integral to authentication and authorization on the app, predictable identifiers via weak PRNG fundamentally compromise the subscription validation's security boundaries.
**Prevention:** Always use a CSPRNG (Cryptographically Secure Pseudorandom Number Generator) such as `self.crypto.getRandomValues()` instead of `Math.random()` when creating identifiers that perform security-sensitive operations or functions (like access binding, tokens, session IDs, etc.).
