## 2025-02-12 - Weak Random Number Generation for Subscription Device ID
**Vulnerability:** The application used `Math.random()` to generate an 8-character `deviceId` in `src/util/subscription.js`. This device ID is included in the JWT payload and used as a security binding to ensure a token is tied to a specific client. `Math.random()` is not cryptographically secure, meaning its output sequence is predictable, potentially allowing an attacker to guess device IDs and impersonate devices or reuse subscriptions if they discover the PRNG state or seed.
**Learning:** Even for seemingly simple local identifiers, if they are used as part of a cryptographic or subscription binding scheme (like in the ECDSA JWT payload verification), they MUST be generated using a CSPRNG. Furthermore, when substituting `Math.random()` with `globalThis.crypto.getRandomValues()` in a React application using Jest/JSDOM, the `crypto` object might not be globally available in the test environment.
**Prevention:** Always use `globalThis.crypto.getRandomValues()` for generating random tokens, IDs, or keys that have any security implication. Ensure that `src/setupTests.js` has a polyfill or conditionally assigns a mock (`require('crypto').randomFillSync`) for `globalThis.crypto` to prevent breaking the Jest test suite.
